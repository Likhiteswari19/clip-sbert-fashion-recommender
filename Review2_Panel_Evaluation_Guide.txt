================================================================================
2. ALTERNATIVE SOLUTIONS & WHY CLIP + SBERT
================================================================================

Approach 1: Traditional Content-Based Filtering
* Uses product attributes only
* Simple, easy to implement
* Limited understanding of images/text

Approach 2: Collaborative Filtering
* Uses user-item interactions
* Good with sufficient history
* Cold-start problem for new products/users

Approach 3: CLIP + SBERT + Interaction-Based (SELECTED)
* CLIP → visual representation (512-dim embeddings)
* SBERT → text representation
* Interaction data → user preference
* Handles new products & sparse history
* More computationally complex

Why NOT only CLIP / only SBERT / only Collaborative Filtering:
* CLIP alone misses textual semantics
* SBERT alone misses visual similarity
* Collaborative alone fails on cold-start
* Combined approach covers all 5 project objectives

3. SYSTEM ARCHITECTURE
================================================================================

Architecture Diagram (Key Components)
-------------------------------------
USER → React Frontend → Backend API
                            ├── Product Search
                            └── Recommendation Engine
                                    ├── CLIP (Image Embeddings)
                                    ├── SBERT (Text Embeddings)
                                    └── User History (Interactions)
                                    ↓
                            Recommendation Score → Recommended Products → Frontend

Data Flow
---------
Product Image → CLIP → Image Embedding (512-d) → Stored
Product Description → SBERT → Text Embedding → Stored
User Preference + Image Sim + Text Sim + Interaction History → Recommendation Score → Results

Database Tables
---------------
* Products (14,959 items)
* Customers
* Transactions/Interactions
* CLIP Embeddings (14,959 × 512)
* SBERT Embeddings
* Recommendation Cache
